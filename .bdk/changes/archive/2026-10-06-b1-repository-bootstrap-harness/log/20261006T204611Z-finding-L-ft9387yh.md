Problem: Severity low, not blocking. The session runtime configuration in harness/providers.ts:42-66 (`permission_mode: bypassPermissions`, `allow_dangerously_skip_permissions`, `allow_all_tools`, `setting_sources: ["project"]`, `apiKeyRequired: false`, and the `env` with `ENABLE_CLAUDEAI_MCP_SERVERS=false`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`) moved under `config.sdk` with unchanged values. It now passes through `callRun` (harness/provider.ts:90-95), which spreads it and adds `working_dir`, `debug_file` and a per-run `XDG_CONFIG_HOME` merged into `env`. Before the fix the same options went to the SDK provider directly, without the per-run fields.

Why it matters: Sessions keep running with permissions bypassed, which is only acceptable because each run is confined to its own working copy and config home; this commit is what makes that confinement real. A future edit that adds an `env` key in providers.ts must keep `envOf` merging it, or the per-run `XDG_CONFIG_HOME` and the git isolation would diverge.

Suggested fix: None required for this range. Confirm in the paid probe (L-5590ogrm) that the session's cwd is the run's working copy and the debug log is under the run directory.
