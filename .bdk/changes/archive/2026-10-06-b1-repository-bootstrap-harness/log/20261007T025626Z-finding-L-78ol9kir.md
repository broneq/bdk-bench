Problem: harness/paths.ts:65 defines resultsFile(resultsDir, suite, series). Plan part 03 task 03-2 specifies resultsFile(suite, series, root = ROOT_DIR) returning <root>/results/<suite>/<series>.jsonl, and its test case resultsFile("smoke","s1","/x") = /x/results/smoke/s1.jsonl. The test in paths.test.ts:99 instead asserts resultsFile("/x/results","smoke","s1"). The module also keeps RESULTS_DIR, cacheHome, seriesDir and seriesNames, which the plan's export list does not name.

Why it matters: later parts written against the plan contract (commands, reports) call the plan signature; a swapped argument order compiles only by accident because all three are strings, and would silently write to the wrong path. The plan and code are two statements of one fact that have drifted (BDK-ARCH-5).

Suggested fix: either align resultsFile to the plan signature and test, or amend the plan part/design to record the (resultsDir, suite, series) form and the extra exports, after checking that every caller uses one form.
