Problem: Severity info. `credentialsProblem` (harness/cli.ts:163-170) checks only that `ANTHROPIC_API_KEY` is non-empty or `claude auth status --json` reports `loggedIn`; it fails closed when the status call throws, and prints no secret. The full process env (key included) passes to promptfoo and, merged, to sessions (tools.ts:43, provider env). Raw `result.json` and copied debug logs go to `.runs/` (gitignored). Sessions run with `permission_mode: bypassPermissions`; the hidden-material read risk is recorded as L-1wrdf16i. No secret reaches a committed file or a log line in the range.

Why it matters: Debug logs under `.runs/` may contain request metadata; they must stay out of git and out of anything uploaded. Because of L-dzhorbso, sessions today would also run without the per-run `XDG_CONFIG_HOME`.

Suggested fix: None beyond L-dzhorbso; keep `.runs/` ignored and never attach raw debug logs to issues.
