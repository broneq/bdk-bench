design.md:83 says "runs in progress finish, so a series overshoots by at most `--concurrency - 1` run caps". Checked against `broneq/bdk` `825455dd`:

- `budget.ts` `assertCanStart` compares only the recorded spend (`spent(ledger) >= budget`); a run is recorded in `afterRun` when it ends (`hook.ts:315`), so in-flight runs are invisible to the check.
- The session cap is static: `maxBudgetUsd: spec.runCapUsd` (`suites/regression/suite.ts:115`), not `runCap(ledger, ...)` per run.

Worst case: a run ends and lifts the ledger to budget - epsilon, the freed slot starts one more run (check passes), the other `concurrency - 1` runs are still in flight; all `concurrency` runs can spend a full cap. Overshoot is up to `--concurrency` run caps (60 USD at the defaults, not 45), plus any `extraCost` (judge calls) on top of the cap. With `--concurrency 1` the statement claims no overshoot, but one run can still spend a full cap. The sentence is copied from the source `evals/README.md:23`, which has the same error.

Fix: state the true bound (and carry it into the README "Budget" section), or, better for a benchmark whose CLAUDE.md says "the ledger caps the total spend", make `startRun` reserve the run cap in the ledger at start and settle it at `afterRun`, so the budget check counts in-flight runs (BDK-EJ-1).
